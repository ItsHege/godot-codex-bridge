# One-click Connect contract (v1)

Local contract, 2026-09-30. The dock's Connect button starts the trusted Host
itself and pairs automatically, replacing the manual terminal launch.

## Why it was disabled, and what changes

Automatic launch was disabled because the addon used to launch whatever the
project-local `host_config.json` named, so project content (including a Codex
agent editing the game) chose what ran. v1 moves that authority out of every
project: the addon only launches what a per-user trust record names.

## Trust record (never inside a project)

`%LOCALAPPDATA%\GodotCodexBridge\trusted_host.json`, written only by
`start_codex_host.ps1 -Trust` (run by the user, or started by the addon after
the user confirms a re-trust dialog):

```json
{ "schema_version": "trusted-host/1", "install_root": "...",
  "start_script": "...\\scripts\\start_codex_host.ps1",
  "powershell_executable": "...\\pwsh.exe",
  "node_executable": "...\\node.exe", "codex_executable": "...\\codex.exe",
  "runtime": "app-server", "port": 49390,
  "fingerprint": "<installation identity sha256>", "trusted_at": "<iso>" }
```

`-Trust` resolves Node from PATH and Codex from the npm native package when not
given, validates them like `-Start`, computes the installation identity and
prints the record. Running `-Trust` is the human approval that `-Start`
otherwise asks for interactively.

## Owned launch (`-Start -OwnerProcessId <pid> -ExpectedFingerprint <fp>`)

- Non-interactive only when: this script is the trust record's
  `start_script`, the executables equal the record's, and the freshly computed
  fingerprint equals both `-ExpectedFingerprint` and the record's fingerprint.
  Otherwise it writes a `fingerprint_changed` / `untrusted` launch status and
  starts nothing.
- The pairing secret comes from env `GODOT_CODEX_HOST_PAIR_SECRET_INPUT`
  (64 lowercase hex, generated by the addon); it is never printed.
- Launch status: `%LOCALAPPDATA%\GodotCodexBridge\launch\<owner pid>.json`
  `{ status: starting|ready|fingerprint_changed|untrusted|failed, message,
     fingerprint, host_pid, port, updated_at }`.
- Lifetime: runs until the Host exits or the owner process exits. On owner
  exit it asks the Host to stop and waits up to 15 minutes, because the Host
  defers shutdown while an addon update is scheduled or installing.

## Addon

- Connect: if a paired Host is already reachable, reuse it. Else, with a valid
  trust record whose files exist, generate the secret, set the env var only
  for the launch, start the record's PowerShell hidden with the owned-launch
  arguments for this project, poll the launch status, connect and pair
  automatically with that secret (no paste).
- `fingerprint_changed`: dialog "The Host installation changed since you
  trusted it (for example it was rebuilt). Trust this version?" showing the
  install path and old/new fingerprint. Confirm runs `-Trust` with the
  record's executables, then connects.
- No trust record: show the one-time setup command
  (`pwsh "<start_script>" -Trust`), where the path comes from host_config.json
  for display only; the manual paste-code flow keeps working.
- Closing the editor stops the owned Host (not while an update is pending).
